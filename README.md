# 区域课程本地化发布

面向东盟多国的国际中文课程本地化发布平台。以一个经过批准的基础课程版本为继承源，
各地区分支提交术语覆盖、案例替换、课时调整和合规说明，平台自动计算上游修订对各地
分支的影响，并按变更类型执行组合审批与发布门禁。

## 领域结构

- `contracts.py` — 基础契约：版本化实体（`BaseCourseVersion`）与关联记录（`LocaleOverride`）。
- `models.py` — 核心模型：变更类型、覆盖项生命周期、基础快照、地区分支、合并视图与内容摘要。
- `approvals.py` — 审批策略：每种变更类型对应固定的审批角色组合
  （语言专家 / 学科负责人 / 合作院校），确认在超时、覆盖项再编辑或基础版本推进后失效。
- `impact.py` — 影响分析：基础版本推进时，标记内容冲突（上游改动了被覆盖的内容键）
  与确认失效，逐地区生成影响报告。
- `release.py` — 发布批次：锁定各地区内容摘要与依赖版本（覆盖项及其版本号），
  地区任务彼此隔离，失败可单独重试；追加式检查点支持进程重启后续接。
- `status.py` — 状态查询模型：地区继承差异、阻断原因、进程续接位置。
- `service.py` — 应用服务 `LocalizationService` 与可整体移交的 `Repository`。

## 关键规则

- 基础课程版本必须经批准才能登记为继承源，且只能向前推进。
- 覆盖项定稿前必须集齐所属变更类型的全部审批角色，且确认未过期、未失效。
- 存在未解决差异（冲突）或过期/失效确认时，发布门禁拒绝创建批次。
- 发布批次创建即锁定各地区内容摘要与依赖版本；单个地区失败不影响其他任务，
  可隔离重试，重启的进程通过检查点接续原来的执行位置。
- 紧急撤回到最近兼容版本（不晚于当前继承基础版本的最近一次成功发布），
  在学校确认前阻断该地区再次发布。
- 状态查询可直接比较两个地区的继承差异、列出阻断原因、给出发布/撤回进程的续接位置。
